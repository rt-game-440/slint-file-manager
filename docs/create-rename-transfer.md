# 新建、重命名与文件传输（Issue #12）

## 用户可见行为

### 新建

- **入口**：Ctrl+Shift+N（新建文件夹）；工具栏“新建”按钮（图标 +）弹出菜单：第一项“文件夹”，其后是系统“新建”模板（读自注册表 ShellNew，只检查一组常见扩展名，支持 NullFile 空文件、FileName 模板文件、Data 内置内容三种；没装对应程序的类型不出现，没有可用模板时只有“文件夹”）。
- **命名**：文件夹默认“新建文件夹”，文件为“新建 模板名.扩展名”（如“新建 文本文档.txt”）；已有同名时自动编号“新建文件夹 (2)”，**不会覆盖或合并**任何已有项目。创建用“不覆盖”的原子原语（`create_new`／`CreateDirectoryW`），并发出现同名也只会失败而不会覆盖。
- **创建后立即重命名**：新项目被选中并滚动到可见，名称处直接是输入框；文件默认只选中不含扩展名的部分，文件夹整段选中。Enter 确定、Esc 保留默认名称。
- 回收站、未读取完成的位置、有对话框或后台操作进行中时不能新建，状态栏说明原因。

### 重命名

- **入口**：F2（只对唯一选中项；多选只提示“一次只能重命名一个项目”）。
- 默认选中范围不含扩展名（`naming::rename_selection`：文件夹与点开头文件整段选中）。
- **提交语义**与资源管理器一致：Enter 提交；点击别处（失去焦点）也提交；Esc 取消。
  - 名称不合法（空、含 `\ / : * ? " < > |`、保留名如 CON、末尾点或空格、过长）或与同目录其他项目重名：**Enter 时留在编辑状态**，输入框边框变红，状态栏说明原因，不改任何文件；**失去焦点时**无法继续编辑，放弃本次编辑并在状态栏说明“没有重命名：…”。
  - 只改大小写不算重名，会真正改变磁盘上的名称。
  - 名称没有变化等于取消。
- 重命名成功后选中改名结果；失败（权限、被占用……）弹说明框并保持原名。

### 复制、剪切、粘贴（与资源管理器互通）

- Ctrl+C／Ctrl+X／Ctrl+V 作用于活动面板。剪贴板格式是 `CF_HDROP` 加 `Preferred DropEffect`（复制 1／移动 2），因此本应用复制的文件可以在资源管理器里粘贴，反之亦然。
- **剪切**不会立刻移动：被剪切的项目整体变淡（不透明度 45%），到粘贴时才移动。剪贴板被别的程序改写（`GetClipboardSequenceNumber` 变化）后，淡化标记自动失效。成功移动后若剪贴板仍是本应用放上去的内容则清空，避免重复粘贴；部分成功时不改写剪贴板（见限制）。
- 粘贴目标是活动面板当前文件夹。粘到文件夹自己里面、粘到自己的子文件夹里一律拒绝并说明，不做任何改动。
- **同名冲突**：弹出应用内对话框“目标位置已有同名项目”，点名冲突项，三个按钮：
  - **保留两者**：新来的改名为“名称 (2)”，已有项目原样不动；
  - **跳过**：不复制这些项目，其余照常；
  - **取消**：不做任何改动。
  没有“替换”选项，文件夹也从不合并（v1 刻意保守，见限制）。

### 拖放

- **应用内**：左右面板之间、面板内拖到文件夹行／格上（该文件夹带蓝色描边高亮）；拖到另一面板空白处 = 放入该面板当前文件夹。指针旁有跟随提示“名称 → 移动到 目标”或“复制到 目标”，不能放置时提示原因（如“不能把文件夹放进它自己里面”“已经在“目录”里了”）。
- **默认语义**：同一磁盘卷默认**移动**，不同卷默认**复制**；按住 Ctrl = 复制，按住 Shift = 移动（与资源管理器一致）。**提示与实际执行共用同一个判定函数**（`evaluate`），不会出现提示“移动”实际复制的情况。
- 多选后在已选项上按下：不拖动、直接松开时才收拢为只选这一项（保证拖多选不会被单击收拢打断）。
- Esc 取消拖动，松开后什么都不发生。
- **拖出窗口**：指针离开窗口后交给系统 OLE 拖放（`SHDoDragDrop`），资源管理器等程序可接收。系统拖放循环是模态的，**拖出期间窗口不重绘**；返回后按结果刷新受影响的目录。
- **从资源管理器拖入**：本应用自己的 `IDropTarget` 接管窗口（替换 winit 的）。悬停时显示同样的提示。释放后：复制 → 本应用复制并回答“复制”；移动 → 本应用自己移动并回答“无效果”（`DROPEFFECT_NONE`），避免来源程序再删一次。

### 失败与如实汇报

- 逐项执行并逐项记录：全部成功只写状态栏一行（“已复制/已移动/已新建/已重命名…”）；有失败时状态栏红色“部分完成：K 项已…，M 项未能…”，并弹说明框列出（最多 8 个）失败项与原因（没有权限、磁盘空间不足、设备已断开、正被占用、项目已不存在、目标文件夹不存在、不能放进自己里面……）。已成功的不回滚，失败的保持原样。
- **用户取消**（系统进度窗口里点取消，对应 `Aborted`）：之后的项目不再执行，**不弹错误框**，状态栏说明“已取消”，已完成的部分如实汇报。
- **跨卷移动**：先复制，目标写完且大小校验一致后才删除源；复制中途失败时源原样保留、目标不留下不完整的副本。
- 绝不静默覆盖或删除用户文件：所有创建／复制／移动／重命名都用不覆盖原语；冲突一律走上面的三选项。

### 要点

- **不重复造轮子的边界**：产品里的复制／移动交给系统 `IFileOperation`（与资源管理器一致的进度、取消、权限、长路径行为）；应用只负责“计划、冲突决策、不覆盖约束、如实汇报”。测试用 `StashBackend` 实现同样的契约并能注入失败。
- **Marks 叠加层**：`cut`／`editing`／`drop` 三种临时标记叠在条目模型上（`ItemsModel` 的 `row_data` 叠加），不进入标签的真实数据，因此刷新目录不会丢标记，也不会污染排序与选择。
- **输入框焦点**：网格与列表两种视图同时实例化，只有当前显示的视图才放 `NameEditor`（`shown` 属性）；否则隐藏视图里的输入框初始化时会抢走焦点。失去焦点提交只在“得到过焦点之后又失去”时触发，避免初始化的 `has-focus=false` 误判为失去焦点。
- **多选收拢延后**：多选里按下已选项时不立即收拢，松开且没有拖动才收拢；拖动开始后整组一起走。
- **修饰键**：真实运行读 `GetAsyncKeyState`；harness 用 `set_keys_override` 注入；OLE 回调直接用系统给的 `grfKeyState`。

## v1 限制（刻意保守，已记录）

- 没有“替换”：同名冲突只能保留两者、跳过或取消；文件夹从不合并。以后做替换需要额外的二次确认与“移到回收站”式的可恢复覆盖。
- 逐项调用 `IFileOperation`：多项复制时系统进度窗口是一项一个，而不是整批一个。
- 系统拖放（拖出窗口）期间窗口不重绘（模态循环）。
- 剪切后部分成功时不改写剪贴板：已移走的项目仍留在剪贴板里，再粘贴会报“项目已不存在”。
- 新建模板只检查一组常见扩展名，不枚举系统里全部 ShellNew 注册；菜单名称用内置中文名而不是系统显示名。
- 本机没有 Windows 11 环境，行为未验证。
