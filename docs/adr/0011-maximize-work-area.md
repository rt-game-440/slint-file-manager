# 无边框窗口最大化只占工作区

状态：已采纳（2026-11-08，Issue #45）。实体显示器、自动隐藏任务栏与多显示器的人眼确认待用户验收（docs/checklist/checklist.md）。

## 决定

| 项目 | 取值 | 依据 |
| --- | --- | --- |
| 最大化尺寸 | 沿用 winit 的处理：客户区 = 窗口所在显示器的工作区（`MONITORINFO.rcWork`） | 实测两种渲染器一致，见下 |
| 自动隐藏任务栏 | 在 winit 处理 `WM_NCCALCSIZE` 之后，对有自动隐藏任务栏的那一边让出 1 像素（`src/render.rs` 的 `keep_taskbar_reachable`，`SetWindowSubclass` 子类，纯函数 `leave_autohide_gap` 有单元测试） | 此时 `rcWork` 等于整块显示器，不让出则鼠标碰边缘唤不出任务栏；系统自带最大化窗口也这样处理 |
| 发布前检查 | `scripts/verify-maximize.ps1`（默认与 `--renderer=software` 两种渲染，四种最大化方式）接入 `scripts/verify.ps1` | 防止回归；只读窗口矩形数值，不保存截图 |

## 实测（开发机，2026-11-08）

环境：Windows 10 22H2（19045），主显示器为远程控制软件的虚拟显示器 3840×2160，200% 缩放，任务栏在底边（`rcWork` = 3840×2080）。窗口样式 `0x16CF0000`（保留 `WS_CAPTION|WS_THICKFRAME` 等，用于 DWM 阴影，系统标题栏由 winit 的 `WM_NCCALCSIZE` 抹掉）。

| 最大化方式 | 默认渲染（femtovg） | 软件渲染 |
| --- | --- | --- |
| `ShowWindow(SW_MAXIMIZE)`（winit／Slint `set_maximized` 同路径） | 客户区 (0,0)-(3840,2080) = 工作区 | 同左 |
| 点击自绘标题栏最大化按钮（`root.maximized = !root.maximized`） | 同左 | 同左 |
| 双击标题栏空白处（同样改 `maximized`） | 同左 | 同左 |
| `WM_SYSCOMMAND` `SC_MAXIMIZE`（Win+↑ 同路径） | 同左 | 同左 |

四种方式还原后都恢复原尺寸。窗口外框矩形为 (-13,-13)-(3853,2093)，比工作区大一圈不可见缩放边框，但客户区与 DWM 可见边界都等于工作区。

winit 0.30.13 源码（`platform_impl/windows/event_loop.rs`，`WM_NCCALCSIZE`）确认：无系统装饰的窗口最大化时把客户区设为 `MonitorFromRect` 选出的显示器的 `rcWork`，所以任意一边的任务栏与多显示器都已覆盖。窗口大小的处理与渲染器无关（渲染器只影响绘制）。

## 与 Issue #45 现象的关系

- **实测**：开发机上没有复现“默认渲染下最大化为整块显示器 3840×2160”。两种渲染下用 Win32 读到的窗口客户区都是工作区 3840×2080。
- **推断**：Issue 报告的 3840×2160 可能来自 #39 之前的构建（透明窗口走另一条合成路径时窗口矩形读数异常），也可能出自自动隐藏任务栏或观察手段（此时工作区确实等于整块显示器）；本机没有证据可以区分，不作为结论。
- 因此本次改动只补上确有缺口的自动隐藏任务栏场景，并加回归检查；若用户在实体显示器上仍复现，请记下显示器布局、任务栏位置与是否自动隐藏（见验收清单）。

## 检查与限制

- `scripts/verify-maximize.ps1 [-Mode all|default|software] [-Diag]`：退出码 0 通过、1 失败、2 无法判断。需要已解锁的交互桌面（真实鼠标点击标题栏）。
- 不测自动隐藏任务栏：切换任务栏设置属于修改系统设置，脚本不做；该场景由 `leave_autohide_gap` 单元测试与人工验收覆盖。
- 双显示器、任务栏在左／右／上边：实现不区分边（用 `rcWork`），开发机只有一块显示器、任务栏在底边，其余为推断，待人工验收。
