# OneDrive／iCloud 无隐式下载浏览

依据 Issue #14、[ADR 0004](adr/0004-visible-thumbnails-and-cloud-downloads.md)、[研究 0003](research/0003-shell-menu-and-cloud-compat.md)。代码：`src/cloud/`（状态判定、守卫、模拟提供方、同步根发现）、`src/browse/entry.rs`（目录读取带云状态）、`src/app/`（提示与确认文字）、`ui/file-views.slint`（状态标记）。

## 一句话规则

**浏览 = 只读元数据。** 目录枚举、云状态判定、缩略图、预览、搜索、目录监视、右键菜单弹出，都不读取云文件的数据流，因此不会让同步客户端下载文件。只有用户明确的动作（打开、复制／拖放、提供方菜单里的“始终保留”）才允许下载，并且界面要让用户看得出来。本应用不登录任何云账户，只认本机已经存在的同步目录。

## 状态与显示

状态用**云文件 API** 判定，而不是只看属性位：默认情况下已下载的云文件与普通文件属性完全一样（都是 `0x20`），只看属性分不出“本地可用”。`CfGetSyncRootInfoByPath` 与 `CfGetPlaceholderInfo`（句柄只带 `FILE_READ_ATTRIBUTES`、不跟随重解析点）只读元数据、不打开数据流。

| 状态 | 判定 | 标记 | 说明文字 |
| --- | --- | --- | --- |
| 仅在线 | 属性带 `OFFLINE`／`RECALL_ON_OPEN`／`RECALL_ON_DATA_ACCESS` | 蓝色云 | 仅在线（未下载到本机） |
| 仅在线，客户端不可用 | 同上，且同步根的提供方状态为断开、断网或出错 | 琥珀色斜线云 | 仅在线，同步客户端当前不可用，暂时无法下载 |
| 本地可用 | 在同步根内、是占位文件、固定状态不是“固定” | 绿色圈内对勾 | 本地可用（已下载，空间不足时可被释放） |
| 始终保留 | 属性带固定位（且没有取消固定位），或占位信息的固定状态为“固定” | 实心绿圈内白色对勾 | 始终保留在本设备 |
| 无 | 不在同步根内、或同步根内没有占位信息的普通文件、或已下载的文件夹 | 无 | 无 |

- 同时带固定位和取消固定位的是 `desktop.ini` 之类的特殊文件，不算“始终保留”（真实环境里确有这类文件，见下文）。
- 文件夹只有带“按需下载”属性（尚未填充）或被固定时才标记；已下载的文件夹不标记，也不向提供方询问。
- 仅在线文件**不**向提供方询问占位信息（属性已足够判定），枚举一个目录只问一次同步根。
- 标记是图标之外的补充，状态的文字说明同时写在条目的无障碍描述里；单选一个云盘项目时状态栏也用文字说明。
- 提供方状态（同步客户端退出、断网、出错）每 2 秒探测一次，变化时静默重读，标记与状态栏警告自动跟上，恢复后自动消失。已下载的文件不受影响，状态栏如实说明“已下载的文件照常可用，仅在线文件暂时无法下载”。

## “浏览 = 下载”入口审计

| 入口 | 可能下载吗 | 处理 | 测试 |
| --- | --- | --- | --- |
| 目录枚举与元数据 | 否 | `FindNextFile` 元数据，不打开文件；云状态来自属性与云文件 API，仅在线文件不询问占位信息 | 单元测试 `browse::entry` 云状态三例；`cloud-real`（见下，三个真实同步根整树枚举，0 水合） |
| 云状态判定 | 否 | `CfGetPlaceholderInfo` 只带属性读取权限；`cloud` 单元测试覆盖分类穷举、提供方状态映射、调用次数 | `cloud::tests`；`cloud-lab`（真实新建、固定、释放、显式读取，状态逐步核对） |
| 缩略图（原生解码） | 否 | `cloud::open_local_only` 守卫：先查属性、打开后在句柄上再查一次；仅在线返回“云端”失败，显示图标 | `cloud` 守卫单元测试；harness `run`“云盘”C2；`cloud-real`（120 个真实仅在线图片，全部被挡住） |

| 目录监视 | 否 | `ReadDirectoryChangesW`，不打开文件 | `cloud-real`（真实根监视 3 秒，事件数记录） |
| 右键菜单弹出 | 否（研究 0003 实测） | 只做 `QueryContextMenu` 枚举；本应用只在用户点选命令后才调用 `InvokeCommand` | 研究 0003；人工清单（对自己新建的测试文件点右键、看水合数） |
| 双击打开 | 是（明确操作） | 打开前状态栏说明“只在云端，正在通过 OneDrive 下载并打开”；提供方不可用时红字说明“仍已请求打开，可能失败” | harness `run`“云盘”C4、D3 |
| 复制／剪切／粘贴 | 复制是；同盘移动否 | 复制时就提示“含 N 个仅在线文件，将通过云盘客户端下载到本机”；粘贴进度里再提示；完成后汇报“其中 N 个仅在线文件已由云盘客户端下载到本机”。同一磁盘上的移动只是改名，不读内容，不提下载 | harness `run`“云盘”C5、C6 |
| 拖出窗口（交给系统拖放） | 是（对方读取时） | 拖出时状态栏说明含仅在线文件、将被下载 | harness `run`“云盘”C7 |
| 应用内拖放 | 复制是；同盘移动否 | 与复制／移动同一条传输路径，同样提示 | 同上 |
| 删除／永久删除 | 否（但会同步到云端） | 确认框加一段说明：位于 OneDrive／iCloud 同步文件夹，删除会同步到云端；只想腾本机空间请取消，改用右键菜单“释放空间”，那不会删除云端文件 | harness `run`“云盘”C8、C9 |

“仅在线”判定之后文件被释放空间的竞态：守卫在读取前后各检查一次，把窗口压到“属性检查与打开之间”；残留窗口内打开一个刚被提供方清空的占位文件，最坏结果是提供方下载该文件（和用户双击一样），没有数据损坏。

## 决定

1. **不向提供方请求缩略图。** 对云占位文件不使用不带 `INCACHEONLY` 的 `THUMBNAILONLY` 请求（研究 0003 观测到 OneDrive 返回 PENDING 后异步缓存、iCloud 当场返回）。理由：这类请求由提供方决定是否下载，应用无法证明不下载；代价是仅在线文件在系统缓存没有缩略图时只显示图标。需要时再单独评审。
2. **状态只信云文件 API 与属性，不信扩展名或路径。**
3. **同盘移动按改名处理**：不读内容，因此对仅在线文件不提示下载。
4. **同步根发现**：读系统同步根注册表（`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\SyncRootManager\<提供方>!<SID>!<账户>\UserSyncRoots`，只读），回退环境变量。iCloud 云盘常被用户移到别的盘，原先只认 `%USERPROFILE%\iCloudDrive` 在这台机器上找不到，已修正；新增“iCloud 照片”入口。

## 真实环境核查

方法（`harness cloud-real`，只读，只输出统计、不含任何文件名或路径，写入 `artifacts/state/cloud-real.json`）：先对每个同步根整树取元数据快照，再用**产品代码**走完所有会碰到内容的入口（全部目录枚举、对抽样的仅在线文件走守卫／预览／系统缓存、搜索遍历、目录监视），最后再取快照。按研究 0003 的水合数方法统计“按需下载”位从有变无的文件，再拆成“本次接触过的抽样文件”和“其余对照文件”，对照组的变化只能是同步客户端自己的后台活动。另用 PowerShell 的 `Attributes` 抽样对照本程序读到的属性。

环境：Windows 10 22H2（19045）、OneDrive 26.198.1011.0006、iCloud for Windows 15.10.39.0（应用商店版）。

| 同步根 | 文件数 | 仅在线 | 文件夹 | 提供方状态 | 抽样接触文件 | 抽样内下载数 | 对照组下载数 | 对照组被清空数 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| OneDrive | 4552 | 4547 | 82 | 已连接 | 64 | 0 | 0 | 0 |
| iCloud 云盘 | 41276 | 41266 | 4410 | 已连接 | 62 | 0 | 0 | 0 |
| iCloud 照片 | 1687 | 1686 | 1 | 已连接 | 72 | 0 | 0 | 0 |

- 枚举与状态：OneDrive 文件 4547 仅在线、3 本地可用（其中 1 个是固定状态为“排除”的特殊文件，按本地可用显示；另有 2 个隐藏的、固定位与取消固定位同时存在且没有占位信息的特殊文件，不列出，也没有被误判为“始终保留”）；iCloud 云盘 41254 仅在线（枚举器看到的数量，隐藏文件不列出）。
- 与 PowerShell 对照：三个根共 2104 个文件，“按需下载”位判断 0 处不一致。
- 守卫、预览与原生缩略图：每个根 40 个真实仅在线图片，原生缩略图全部为“云端”、预览全部被挡住；共 198 个仅在线文件（含文档与视频）的 `open_local_only` 全部被挡住。
- 系统缩略图仅缓存：OneDrive 图片 40/40 为“不支持”（系统缓存里没有）、视频 4/4 有缓存；iCloud 照片 19/40 图片与 17/20 视频系统缓存里已有（直接显示，没有下载）。
- 搜索与监视：三个根的搜索遍历与 3 秒目录监视期间，同样没有任何文件被下载。搜索不进入隐藏文件夹，所以遍历的文件夹数少于整树快照（iCloud 云盘有 20 个隐藏文件夹）。
- 观察窗口内（整个核查约 16 秒）同步客户端自己没有下载或清空任何文件，因此这次没有机会观察到后台活动的混入；要区分背景噪声需要更长的窗口或同步繁忙时再测（见人工清单）。

受控实验（`harness cloud-lab`，只在本命令新建的 `sfm-issue14-test-*` 临时文件夹里做事，用户原有文件一个未碰）：新建 3 个小文件 → 等提供方接管应为“本地可用” → 设“始终保留”（`attrib +P -U`）→ 设“释放空间”（`attrib -P +U`）→ 对仅在线文件走全部不应下载的入口并核对没有被下载 → 显式读取一次（相当于用户明确打开）确认水合检测有效 → 恢复固定状态并逐个核对 → 删除测试文件夹并核对。

| 提供方 | 新建后变为本地可用 | 设始终保留 | 释放空间 | 浏览入口后仍为仅在线 | 显式读取后变为本地可用 | 恢复并逐个核对 | 测试文件夹删除 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| OneDrive | 通过 | 通过（立即） | 通过（约 0.5–9 秒，提供方异步执行；其中一个文件在第一次实验里 150 秒内没有被释放，第二次 0 秒就被释放） | 通过 | 通过 | 通过 | 通过 |
| iCloud 云盘 | 通过 | 通过（立即） | 通过（约 2.5 秒） | 通过 | 通过 | 通过 | 通过 |

- 释放空间是提供方的异步行为，不是应用能控制的：OneDrive 对同一批文件的释放时间并不一致，界面标记以提供方实际状态为准，不做乐观更新。
- 在云盘里删除测试文件夹会同步到云端并进入提供方的回收站（OneDrive 回收站保留一段时间，由账户自己清理）；这是本次实验唯一留在云端的痕迹，用户可在提供方回收站里清除。

## 版本限制与未验证项

- iCloud：只验证了 iCloud for Windows 15.10.39.0（应用商店版）。它使用云文件 API，“释放空间／始终保留”与 OneDrive 同机制；旧版或非商店版是否同样使用云文件 API 未验证。iCloud 照片的 `Photos` 目录是单层大目录（1687 文件），不是常规的相册层次。
- iCloud 云盘常被用户移动到别的盘，本应用依赖同步根注册表发现它；注册表中没有登记的第三方方式不识别。
- 同步客户端退出与断网：状态映射（断开、断网、错误）由单元测试与 harness 模拟提供方覆盖，真实的“退出客户端／断网”没有在本机模拟（不禁用网卡，不结束用户的同步进程），写入人工清单。
- 系统缩略图缓存里有、而原图仅在线的情况（iCloud 照片约一半）显示的是系统缓存的缩略图，不触发下载。
