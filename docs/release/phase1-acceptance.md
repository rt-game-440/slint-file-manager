# 第一阶段验收报告（Issue #15）

日期：2026-11-08。范围：Issue #1 第 1 阶段“独立文件管理器”的集成与发布验证。本单只做集成与发布验证，发现的缺陷单开 Issue，不在本单里大改。

## 结论（先看这一段）

**不能宣称第一阶段完成。** 在“无头渲染＋渲染器自报帧时间”的口径下，自动化验证和性能目标都通过；但“用户能在真实屏幕上看到并使用窗口”这个前提还没被证实，人工验收尚未开始，Windows 11 没有验证：

1. **疑似阻塞缺陷（待实体显示器确认，#39）**：默认渲染器（femtovg）下，应用窗口在开发机的屏幕合成结果里是透明的，所有外部抓取都只拿到窗口后面的桌面（软件渲染正常）。开发机有混杂条件（混合 GPU＋两个远程控制虚拟显示驱动，主显示器是虚拟显示器），所以这**可能是环境相关**；是否在实体显示器上复现**未确认**。确认动作与判定分支见 [缺陷与已知问题](#缺陷与已知问题)。
2. 61 个既有人工验收项＋本单新增 3 项（见 `docs/checklist/checklist.md` 末尾“第一阶段总验收”）全部未做；其中包含需要真实 U 盘、云盘客户端、Everything、NanaZip、资源管理器拖放的场景，只能人工。
3. Windows 11 x64 完全没有验证（Issue #2 因此一直开着）。
4. 分发包在**真正干净的机器**上的启动没有验证；开发机上做了导入表分析和隔离启动，并发现、修复了一个真实问题（缺 VC 运行库，见“分发”）。
5. 规格里“全盘入口始终可见”目前不满足（#40，规格偏离，不只是视觉差距）。

按 Issue #1 的阶段门槛“关键场景通过验证；性能按约定目标验收”：自动化覆盖到的场景通过、性能在自报口径下达标，但上面的缺口意味着门槛未满足。逐项对照见下一节。

### 无头测试稳定性（已知问题 4）

在当前 main 上连续跑 `verify-harness.ps1`：**3 次完整运行全部通过**。另有 1 次在 Get-FileHash 步骤失败，原因是我自己的启动方式（子进程继承了 pwsh 7 的 `PSModulePath`，Windows PowerShell 5.1 找不到 `Get-FileHash`，与仓库无关）；这次不计入通过次数，它之前的步骤（clippy、交互脚本、同步、右键菜单、搜索、截图对比、动画采集）当时都通过。因此：此前观察到的偶发失败（#7 C9/C17、#8“找不到 ListItem”、#12／#13 时序）在本次“单进程独占机器、没有其他工作树并行”的条件下**没有复现**。

关于原因：`docs/debug-harness.md` 把偶发失败归因于多个工作树共用 `%TEMP%\sfm-harness`、样例目录被彼此重建，并要求并行运行时设置 `SFM_HARNESS_DIR`。这是文档里的**假设**，本单没有做“故意并行以复现失败”的实验，不能算已核实。样本只有 3 次，只能说明没有高频的确定性失败，不能证明不存在低概率时序问题。不单开缺陷，保留为观察项：下次再出现时记录是否有并行 harness、机器负载和失败步骤。

## 分发（启动／更新／移除）

分发方式：**便携 zip**（`dist/slint-file-manager-<版本>-win-x64.zip`，内含 exe 与 LICENSE），没有安装程序。

- 验证方法：`scripts/verify-dist.ps1`——解压到全新临时目录（路径含空格与中文）、解析 exe 的导入表（含延迟加载表）、PATH 精简为系统目录、全新数据目录启动 `--smoke`（会创建真实窗口并初始化渲染器，运行约 1 秒后退出码 0）。
- **发现并修复的问题**：原先的 exe 动态依赖 `VCRUNTIME140.dll`，而分发包不含它，没装 VC++ 可再发行组件的机器无法启动，与“包内包含实际需要的运行依赖”相违。修复是 `.cargo/config.toml` 里一行 `target-feature=+crt-static`（属于本单允许直接修的一两行打包问题）。修复后静态与延迟加载导入表里没有 VC 运行库，只剩 Windows 自带 DLL（含 Universal CRT 的 api-ms-win-crt-*）；**运行时 `LoadLibrary` 的动态依赖无法由导入表证明**。exe 从 22.48 MB 变为 22.66 MB，`verify.ps1` 与 `verify-harness.ps1` 在新设置下全部通过。
- 启动：解压后双击 exe；不需要安装。代码里的注册表访问都是只读（读代码得出的结论，没有用进程监视器核对）；启动前后只比对了解压目录的文件数，没有比对内容和时间戳。用户数据只在 `%LOCALAPPDATA%\slint-file-manager`（会话、设置、缩略图缓存），`--data-dir=` 或 `SFM_DATA_DIR` 可改。外壳扩展（NanaZip、OneDrive）加载后的写入行为未覆盖。
- 更新：用新版 zip 覆盖解压目录里的 exe；用户数据在别处，不受影响。**没有自动更新**，也没有跨版本数据迁移的实测；会话文件版本更新时旧程序会备份原文件并使用默认会话（`verify-session.ps1` 覆盖）。
- 移除：删除解压目录；可选再删除 `%LOCALAPPDATA%\slint-file-manager`。
- 局限（必须明确）：**这不是真正干净的机器**。开发机系统目录里可能有 VC 运行库，所以“能启动”不是证明，导入表分析才是依据；也没有在虚拟机、Windows 沙盒或 Windows 11 上启动过。**没有在“没有可用 OpenGL”的环境验证窗口创建**；软件渲染只在 OpenGL 初始化失败时才回退（见 #39）。exe 静态导入 `cldapi.dll`（云文件 API，Windows 10 1709 起才有），更早的 Windows 10 会因此无法启动；ADR 0008 只承诺并验证了 22H2。exe 没有数字签名，SmartScreen 可能拦截；没有图标与版本资源。
