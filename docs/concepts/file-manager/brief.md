## 约束

- 桌面横向画幅 1536×1024；画面完全由单个应用窗口内容填满，不出现设备外壳、桌面背景、宣传文字或多屏拼贴。
- 项目当前未发现现成 `.slint` 界面、设计 token 或品牌规范；配色、密度、分栏比例和表面材质均为候选方案。
- 无已确定品牌名或 logo，窗口仅标注通用的“文件管理器”。
- 简体中文界面；可出现规格明确的 OneDrive、iCloud、NanaZip 名称，不添加其他品牌。
- 保留可识别的侧栏和地址栏、两组独立标签。C 方向可以增加图片预览浮层，但不能变成三栏文件浏览器或独立图片编辑器。
- 不展示 AI 搜索、照片识别、评分、编辑、同步仪表盘、订阅、账号中心、目录同步或自定义传输队列等未获规格授权的功能。

## 场景与占位内容

共同场景是整理一组图片，左右浏览面板分别显示来源与目标位置。其依据为 F2、F5、F6、F8；实际位置名称、照片主题和数量均是画面占位，不是新增产品能力。

- 虚构目录标签：“图片”“视频”“素材”“整理”；示例路径“此电脑 > 图片”“此电脑 > 整理”。
- 示例文件名仅用 `001.webp`、`002.webp` 等短名称，以及少量 `.jpg`、`.png`；不使用用户的真实目录或文件名。
- 缩略图是生成的山景、树林、海岸、城市建筑等中性示意照片；不会上传或复刻用户的私人图片。
- 屏内功能文案限于：“文件管理器”“收藏”“此电脑”“OneDrive”“iCloud”“回收站”“搜索当前目录”“全盘”“新建”“复制”“粘贴”“删除”“排序”“视图”“双栏”“预览”“打开”“重命名”“属性”“NanaZip”。允许用图标替代部分动作标签。
- 文件大小、日期、行数等如需出现，仅为非权威占位；不显示真实磁盘容量、缓存命中率或实测速度。

## 开放问题与三个方向

| 编号 | 方向 | 对开放问题的回答 |
| --- | --- | --- |
| A | 熟悉均衡 | 以明亮中性表面、等宽双栏和较舒展的图片网格，探索最接近熟悉文件管理布局的日常方案。 |
| B | 紧凑工作台 | 以扁平紧凑工具栏、左侧密集缩略图和右侧详细列表，探索更多文件同屏以及原生右键菜单的融合。 |
| C | 媒体优先 | 以深色低干扰表面、宽来源面板／窄目标面板和轻量预览浮层，探索看图整理时的视觉重心。 |

待用户判断的是信息密度、两侧比例、层级、表面语言、图片与操作控件的权重，以及预览出现后的空间关系；不是重新决定功能范围。

## 第二轮：Linux／macOS 视觉语言

用户于 2026 年 11 月 7 日提出“能不能做 linxu/macos 系那种风格”，作为新的视觉方向要求。此处按 Linux／macOS 风格理解，目标平台仍为 Windows 10／11，不新增跨平台承诺，与正式规格不冲突。第一轮图保留，用户尚未逐张给出最终通过或淘汰结论。

第二轮重新组织窗口顶部、导航、控件密度与表面语言，不只是替换主题颜色。M1–M7 继续适用；为便于纯粹比较主界面，第一轮 B 的右键菜单和 C 的预览浮层不作为本轮必需展示项，其功能范围保持不变。

| 图像编号 | 方向 | 结构与视觉回答 |
| --- | --- | --- |
| A2 | macOS 灵感 | 标题与图标工具栏融合、柔和分层侧栏、低对比页签和等宽双网格；通过细节和留白获得轻盈感。 |
| B3 | GNOME 灵感 | 简洁 Header Bar、较少全局动作、明确的圆角导航组和面板内独立控制；用更大的主体区域减少界面噪声。 |
| C2 | KDE 灵感 | 深色扁平分层、紧凑工具栏与标签带、网格／详细列表并排、清晰状态条；保留较高信息密度。 |

B3 的编号跳过 B2，是因为 B2 已用于第一轮 B 的文字修复。第二轮三个图都按新结构重新生成，不把旧图简单换色。窗口右上仍保留最小化、最大化、关闭入口，使用通用文件夹／云图标，不添加 Apple／GNOME／KDE 的产品标志、操作系统 Dock、桌面、触摸手势或已实现动画的暗示。展示图标按钮可替代部分文字命令，允许使用菜单收纳不常用操作，搜索范围仍要可见。

本轮用户结论：A2 通过，B3、C2 淘汰。采用 A2 的 macOS 灵感视觉语言；具体可照做与不作依据的部分以 [concept.md](concept.md) 为准，细节和动态行为在交互原型中验证。
