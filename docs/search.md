# 目录与全盘搜索

Issue #11。基本搜索（自研遍历）始终可用；Everything 作为可选增强，未安装也不影响使用（[ADR 0007](adr/0007-optional-search-backend.md)）。后端比较与集成契约见 [research/0011-search-backend.md](research/0011-search-backend.md)。

## 使用

- 工具栏右侧的搜索框：输入后约 250 ms 自动开始搜索，Enter 立即开始；Ctrl+F 聚焦搜索框。
- 范围：**目录**（当前活动面板所在目录及其子目录）与**全盘**（本机可见的全部磁盘：固定磁盘、已连接的移动磁盘，以及不在这些磁盘上的云盘本地目录）。目录范围在第一次搜索时锁定，之后在结果里切换目录／全盘范围不会跟着导航变化。
- 搜索中结果分批出现，状态行显示已扫描的文件夹数与条目数；可点“取消”（或 Esc 关闭整个搜索）；取消后迟到的结果一律丢弃。
- 结果列表：单击选中；方向键／PageUp／PageDown／Home／End 移动；Enter 或双击使用默认方式打开（文件夹进入，文件交给系统默认程序）；“在文件夹中定位”回到所在目录并选中该项；Esc 关闭搜索回到原来的面板。
- 搜索期间，面板被结果覆盖，除 Ctrl+F 外的文件快捷键与删除按钮暂时不可用，防止对看不见的面板误操作。
- 不会读取文件内容，也不会因为搜索而触发云文件下载。

## 查询语法（两种后端共用）

不区分大小写；多个条件用空格分隔，表示“并且”。

| 写法 | 含义 |
| --- | --- |
| `report` | 名称包含 `report` |
| `.pdf`、`ext:pdf`、`ext:jpg;png` | 扩展名匹配（只匹配文件，文件夹没有扩展名） |
| `path:docs`、含 `\` 或 `/` 的词 | 在完整路径中匹配 |
| `*.log`、`re?ort` | `*` 任意多个字符、`?` 单个字符；通配词匹配整个名称 |
| `"my file"` | 引号内的空格按普通字符 |

## 状态与提示

一次搜索只有一个结果集，来源明确：

| 情形 | 界面表现 |
| --- | --- |
| 扫描中 | 状态行“正在扫描… 已找到 N 项，已扫描 M 个文件夹”；结果增量出现 |
| 完成有结果 | 状态行“搜索完成：共 N 项（用时…，扫描…）”，附被跳过项说明；状态栏“搜索结果：N 项” |
| 完成无结果 | “已搜索完毕，没有找到匹配项”空状态；只有在扫描完整完成且无错误时才这样显示 |
| 无权限文件夹 | 跳过并计数，状态行写出“已跳过 N 个无权限的文件夹”，不当作“没有结果” |
| 符号链接／联接点 | 不进入（避免环路），计数 |
| 云文件夹未同步到本机 | 不展开（避免触发下载），计数 |
| 命中超过 20000 项 | 截断并明确提示“结果过多，仅显示前 20000 项，请缩小条件” |
| 全盘范围里的离线／未就绪磁盘 | 状态行写明“N 个位置不可访问（磁盘已移除或未就绪）”；若没有任何可用磁盘，显示“搜索范围不可访问：没有识别到可用的磁盘”而不是空结果 |
| 选中项已被删除（结果陈旧） | 该行标灰并说明已不存在，打开时给出提示，不崩溃也不静默失败 |
| 搜索被取消 | 显示“已取消：已显示 N 项，未扫描完，结果不完整” |

### 增强后端的状态区分

`Availability` 五种状态各自有不同的界面表现，且**回退时不混入陈旧结果，也不会把故障显示为空列表**：

| 状态 | 含义 | 表现 |
| --- | --- | --- |
| `NotInstalled` | 没有安装 Everything | 只在“搜索能力”文字里写“基本搜索（未检测到 Everything）”；不弹提示条 |
| `NotRunning` | 已安装但没运行 | 提示条：“Everything 已安装但未运行，本次使用基本搜索…” |
| `IndexLoading` | 正在加载索引 | 提示条：“Everything 的索引尚未就绪，本次使用基本搜索…” |
| `Failed`（探测阶段） | 窗口存在但无回应 | 提示条：“无法与 Everything 通信（原因），本次使用基本搜索” |
| 查询中途故障（超时、回复异常、中断） | 增强已开始返回后失败 | 发 `Reset` 清空已收到的增强结果，用基本搜索重做同一个查询；提示条写明“Everything 查询失败（原因），已改用基本搜索重新搜索” |

增强返回的结果不被直接信任：按本应用的查询规则二次过滤、按范围裁剪、剔除磁盘上已不存在的陈旧索引项（计数并在状态行写明“已剔除 N 条已不存在的索引项”）。

环境变量 `SFM_SEARCH_BACKEND=basic` 强制只用基本搜索（排错与对比速度用）。

## 代码结构

| 位置 | 内容 |
| --- | --- |
| `src/search/query.rs` | 查询解析与匹配 |
| `src/search/walk.rs` | 基本搜索：广度优先遍历；只用目录项自带元数据；全盘范围每个根一个线程 |

| `src/app/search.rs` | 控制器：防抖、会话号（丢弃过期事件）、选择／打开／定位、状态文字 |
| `ui/search.slint` | 搜索框、范围按钮、结果面板 |
| `src/bin/harness/search.rs` | 搜索脚本（45 步）、场景环境、真实规模测量 |

## 测试

- 单元测试：查询、遍历（符号链接环、无权限目录、取消、截断、云文件夹）、引擎（五种可用性状态、中途故障回退、陈旧项剔除、取消）、Everything 报文编码与解码、控制器文字。`cargo test --lib --jobs 6`。
- Harness 搜索脚本：`powershell -File scripts/harness.ps1 search`（模拟增强后端，搜索任务手动驱动，结果确定）；覆盖增量、取消、旧结果不混入、选择／打开／定位、过期结果、五种故障回退。
- 截图基线：11 个 `search-*` 场景 × 100%／150%，详见 [debug-harness.md](debug-harness.md)。工具栏新增了搜索框，所以**所有旧基线都已重新生成，差异仅限工具栏搜索框区域**。
- 模拟后端测试不代表真实 Everything 的行为；真实联调列入 `docs/checklist/checklist.md`。

## 规模与耗时（基本搜索，仅统计，不含路径与文件名）

测试机：Windows 10，3 个本机磁盘；release 构建；`search-bench`（只输出统计）。扫描量由本机实际数据决定，不是人为构造。

| 范围 | 文件夹 | 条目 | 无命中查询，耗时（3 次） | 备注 |
| --- | --- | --- | --- | --- |
| 用户目录 | 34,814 | 245,061 | 6.96 s（首次，冷缓存）、2.00 s、1.99 s | 约 35k 条目/s（冷）→ 约 122k 条目/s（热） |
| 全盘（3 个磁盘） | 441,602 | 3,709,379 | 49.2 s（首次，冷）、17.3 s、17.2 s | 51 个文件夹无权限被跳过；7,627 个链接被跳过；云文件夹未展开 0 |

有命中的查询（`.json`，用户目录，6,809 项命中）：首个结果出现在 16–22 ms，总耗时 3.3–4.8 s。

测量说明：

- 测量时本机有其他程序在编译和运行，耗时波动明显（同一查询重复运行，用户目录 2.0–4.6 s），表中的数字只表明量级，不是性能保证。
- 首次运行明显慢于重复运行，主要是文件系统缓存；“热”数据不能代表用户第一次全盘搜索的体验——全盘首次搜索在这台机器上接近一分钟。
- **没有 Everything 的实测对比**：本机未安装 Everything，增强后端与基本搜索的速度差没有数据，不写推测值。
- 全盘搜索期间 CPU 与磁盘占用、对界面流畅度的影响没有定量测量，只在人工验收里目视确认。

## 已知限制

- Everything IPC 传输层没有与真实程序联调（见研究文档“尚未验证”一节）。
- 基本搜索不使用索引：全盘首次搜索需要数十秒，之后受系统缓存影响才变快；没有持久索引。
- 命中上限 20000 项、遍历深度上限 128；超出会明确提示截断。
- 隐藏项被跳过（与浏览视图默认一致）。
- 不搜索文件内容。
