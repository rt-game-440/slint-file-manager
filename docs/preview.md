# 图片大图预览

依据 Issue #13。代码分两层：

- `src/preview/`（与界面无关，带单元测试）：`mod`（格式识别、原尺寸解码、上限、失败分类、GIF 多帧）、`loader`（后台加载器：一个线程、只处理最新请求）。
- `src/app/preview.rs`（界面接线）与 `ui/preview.slint`（全窗口覆盖层）：会话状态、快照、代号、GIF 计时器、打开动画。

视频缩略图与系统缩略图回退见 [thumbnails.md](thumbnails.md#系统缩略图shell回退issue-13)。**不内置播放器**；预览只做图片，不做任何编辑。

## 操作

| 操作 | 效果 |
| --- | --- |
| 活动面板里按 `Space`（光标所在项；没有光标取第一个选中项） | 打开预览。不是可预览图片时只在状态栏说明原因（如“这种类型不支持预览”），不打开任何界面 |
| `←`／`→`（`PageUp`／`PageDown`） | 上一张／下一张（同一目录、打开时的排序顺序）；`Home`／`End` 跳到首／末张；到头不循环 |
| `Esc`、`Space`、“关闭预览”按钮 | 关闭，回到打开前的选择与键盘焦点 |
| `0` 或 `F`、按钮“适应窗口” | 适应窗口（默认，不放大超过原始尺寸） |
| `1`、按钮“100%” | 1:1 查看（原始像素），大于窗口时可滚动查看 |
| `P`、按钮“播放动画／暂停动画” | 仅 GIF：播放／暂停 |
| 双击文件 | 仍然用系统默认应用打开，与预览无关 |

## 行为约定

- **从哪个面板打开**：预览的是活动面板当前标签里的图片；预览的图片列表是**打开瞬间的快照**（该标签全部可预览图片，当前排序顺序），之后目录变化、另一面板切换标签都不影响预览。右面板的预览不影响左面板的标签。
- **不碰选择**：预览期间不改变任何标签的选择、光标与排序；关闭后选择、光标、键盘焦点、单双栏布局都与打开前一致。
- **后台解码**：图片在后台线程原尺寸解码，界面线程只做包装，任何时候不阻塞。切换时旧图保持显示，右下角提示“正在加载”；新图就绪后替换。
- **最新请求胜出**：加载器同一时刻只做一次解码，连按方向键时中间的请求在轮到之前被取代而跳过；已经开始的解码无法中断，完成后若已过期（代号不是最新）直接丢弃。因此快速切换不堆积线程、不堆积内存。
- **快速开关无残留**：关闭时代号加一，晚到的结果被丢弃，同时释放图像、停止 GIF 计时器。同一时刻最多持有一张图（动图则是它的全部帧）。
- **打开动画**：覆盖层淡入 160 ms、ease-out，不平移不缩放（几何固定），关闭即时。曲线由 `frames --scenario preview-appear` 逐帧采集并断言（单调、无过冲、时长 160 ms）。
- **不透明背景**：覆盖层不透明（`#101318`），不依赖模糊或透明合成，真实窗口与离屏渲染一致。

## 格式与上限

- **格式**：与缩略图原生路线一致——WebP（静态）、JPEG、PNG、GIF、BMP，**按内容识别**（文件头），扩展名只决定“要不要尝试”。JPEG 按 EXIF 方向校正。
- **TIFF／HEIC／视频不在应用内预览**：它们只有系统缩略图（256 像素），放大没有意义，空格时状态栏提示“这种类型不支持预览”。
- **APNG**：显示默认图（第一帧），不播放；**动画 WebP** 判为不支持。
- **上限**（`preview::Limits`）：文件 256 MiB；总像素 5000 万（约 200 MiB RGBA）；单边 16384（常见 GPU 纹理上限）；动图解码后 192 MiB 或 1000 帧，超过时只保留第一帧并在界面附说明，不静默截断动画。超限给出明确的“过大”状态，不尝试解码。
- **云端占位文件**（脱机、访问时召回）不读取内容，避免隐式下载，显示“云端文件”状态。

## 状态与失败

覆盖层的状态（`PreviewState`）：`loading`（首次加载中）、`ready`、`failed`。失败原因（界面文字与无障碍标签“预览失败原因”）：

| 代码 | 含义 |
| --- | --- |
| `missing` | 文件已不存在或无法读取（被删除、移动或没有权限） |
| `cloud` | 云端占位文件，未下载，不会触发下载 |
| `corrupt` | 内容损坏或无法解码 |
| `too_large` | 超过上限（文件体积、像素数或单边） |
| `unsupported` | 不支持的格式 |

失败时仍可用 ←／→ 切换到其他图片，Esc 关闭。

## GIF 播放策略（原型，待用户确认）

决定“打开动图预览时默认自动播放，还是只显示第一帧、由用户手动播放”。两种都已实现，可随时对比；**当前默认值是自动播放（临时），最终选择待用户在验收清单中确认**。

| | 自动播放（当前默认） | 默认第一帧 |
| --- | --- | --- |
| 打开时 | 立即循环播放，与浏览器、资源管理器预览一致 | 显示第一帧，按 `P` 或点“播放动画”才播放 |
| 优点 | 直观，动图“活”着 | 不分散注意力、省电省 CPU；与缩略图“取第一帧”规则一致；看截图类 GIF 更稳 |
| 缺点 | 持续占用计时器与重绘；快速翻看多张动图时画面不停 | 想看动画要多一步操作 |
| 设置 | `settings.json` 无设置或 `"preview_gif_autoplay": true` | `"preview_gif_autoplay": false` |

无论默认值如何，预览中随时可用 `P` 或按钮暂停／播放；切换到别的图片时按默认值重新开始。设置项只在 `settings.json`（`%LOCALAPPDATA%\slint-file-manager\settings.json`）里，**尚未做界面开关**：用户确认策略后再决定是否做开关或固定一种。对比截图见 `artifacts/issue-13-review/`（`gif-playing` 与 `gif-first-frame`）。

## 观测与测试

- 单元测试：`src/preview`（格式、方向、上限、动图延迟与帧数上限、损坏、加载器的最新请求语义）、`src/app/preview.rs`（`preview_gif_autoplay` 读取）。
- harness 脚本 `run` 的 `preview` 段（见 [debug-harness.md](debug-harness.md)）：从正确面板打开、加载中与就绪、切换时旧图保持、GIF 播放／暂停／按钮、首末张与不越界、云文件失败（系统缩略图调用不增加）、适应窗口与 1:1 的尺寸关系、Esc 关闭后选择／光标／焦点恢复、不可预览项的提示、双击仍打开默认应用、预览期间键盘鼠标隔离、30 次快速开关无残留、过期结果被丢弃、损坏／过大／缺失状态、右面板预览不影响左面板标签。解码用 `Loader::Manual`，由 `pump_preview` 确定地推进。
- 截图基线（`preview-*` 8 个场景 × 100%／150%）：`preview-fit`、`preview-one-to-one`、`preview-loading`、`preview-failed`、`preview-too-large`、`preview-gif-playing`、`preview-gif-first-frame`、`preview-text-scale-150`。
- 动画逐帧：`frames --scenario preview-appear --duration 320`，产物在 `artifacts/frames/preview-appear_1100x720_100/`。
- 真实窗口的流畅度、实际图片的观感只能人工确认，见验收清单。
